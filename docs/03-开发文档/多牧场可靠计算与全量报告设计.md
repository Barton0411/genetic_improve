# 多牧场可靠计算与全量报告设计

## 1. 目标与边界

多牧场模式不是把全部牧场拼成一个超大单场项目，而是一个可恢复的任务容器：

- 一个父级牧场组对应多个不可变 `task_id` 的单牧场子项目；
- 每个牧场独立下载、分析、生成单场 Excel，单场失败不能终止后续牧场；
- 最终汇总只读取已经提交并通过校验的子项目结果；
- 跨牧场明细必须全量交付，Excel 行列上限只决定分卷数量，不能造成截断；
- 程序退出、单个子进程崩溃、磁盘不足或汇总中断后，可以从最近的已提交阶段继续。

“任意数量”不能理解为无视物理磁盘、单个文件损坏或运行时间，但系统不得设置一个
因为实现方式导致的牧场数或总行数上限。规模增加时，应主要增加磁盘占用、分卷数量和
运行时间，而不是让内存随全部牧场数据线性增长。

## 2. 用户看到的交付物

最终牧场组报告是一个完整报告包，而不是单个无限膨胀的工作簿：

```text
reports/
├── .group_report_输入摘要.resume/          # 未完成批次，仅用于断点续跑
└── 牧场组报告包_时间_输入摘要/
    ├── batch_manifest.json
    ├── publication_snapshot.json
    ├── 牧场组育种分析汇总报告.xlsx
    ├── 牧场组结果文件清单.json
    └── 完整明细/
      └── 牧场组牛只完整排名明细/
        ├── manifest.json
        ├── 有效在群完整排名_第0001卷.xlsx
        ├── 有效在群完整排名_第0002卷.xlsx
        ├── 全部源行分类对账_第0001卷.xlsx
        └── ...

group_store/
└── current_group_report.json              # 唯一正式报告指针
```

汇总 Excel 只保存适合横向比较的指标、完整性校验和索引，不重复装入所有宽表。
完整牛只排名和全部源行对账按行数、列数和临时 XML 字节预算自动分卷。其他分析明细保留在每个子项目，
并由“全部结果文件索引”逐文件列出相对路径、文件大小、SHA-256 和各 Sheet 的行列数。
因此用户可以从汇总进入单场结果，也可以核对每一份明细文件，数据不会因为总量过大而
只展示 Top-N 或前若干行。

目录可见不等于正式发布；只有通过所有校验并被 `current_group_report.json` 原子指向的
不可变报告包才是当前正式结果。程序若在目录提升或指针切换之间退出，旧指针仍有效，
新候选不会被界面误认。

## 3. 不可破坏的数据不变量

正式发布汇总前必须同时满足：

1. **任务身份不变量**：父任务 `task_id`、子项目 `group_task_id` 和 API farmcode 一致；
   不能按列表位置或仅按可能重复的业务牧场编号关联。慧牧云 API farmcode 与业务
   “牧场编号”是两列不同身份，必须同时保留，不能互相覆盖或因数值相同而合并。
2. **阶段输入不变量**：每个阶段提交清单记录上游文件 SHA-256、行数、配置摘要和软件
   版本；上游或配置变化后，下游阶段自动变为 `stale`。
3. **完整性不变量**：每个源文件的非空数据行必须且只能进入“有效排名”或“未排名对账”
   其中一类；`源行数 = 有效排名行数 + 未排名行数 = 对账导出行数`。
4. **导出不变量**：每个分卷写入临时文件，关闭后验证 XLSX 结构、CRC、行数和 SHA-256，
   通过后才原子改名；任何一卷失败，整个新批次不得标记为正式。
5. **口径不变量**：跨场排名的指数列和权重配置在汇总开始时冻结；不同牧场指数列不一致
   时停止正式汇总，不能把缺失值补零后参与排名。指数排序保存规范化精确十进制文本，
   不得先降为二进制浮点数；极近小数也必须按原值排序。
6. **选择快照不变量**：开始汇总时冻结纳入范围的 `selection_revision`；生成期间范围发生
   变化时，本批次保留为临时结果但不能标记 `current`。
7. **全量文件不变量**：每个阶段 committed manifest 登记的全部正式输出都必须进入受管
   文件清单；损坏、缺失或扫描时变化会阻止发布。历史或未受管的当前可见文件可单独列入
   索引并标记 `managed=false`，但不能反过来污染正式完整性判断。

## 4. 子任务状态机

每个牧场按下列状态独立运行：

```text
pending
  -> data_running
  -> data_committed
  -> analysis_running
  -> analysis_committed
  -> child_excel_running
  -> child_excel_committed
  -> completed
```

任一运行状态可以转为 `failed`、`paused` 或因进程退出转为 `interrupted`。重试从第一个
无效或过期的阶段开始。不得用“某个文件存在”代替阶段完成；阶段完成的唯一凭据是原子
写入且验证有效的 `stage_manifest.json`。

每个阶段清单至少记录：

- `task_id`、牧场编号、阶段名、状态和完成时间；
- 直接输入文件的相对路径、字节数、SHA-256、行数；
- 所有必需输出的相对路径、字节数、SHA-256、工作表行列数；
- 算法配置摘要、指数口径、应用版本；
- 母牛号多重集指纹、牧场归属不一致行数和重复牛号数。

重试不删除旧输入或旧结果。新结果在临时路径生成，完整校验后原子替换，并最后提交阶段
清单。这样程序在写到一半时退出，不会把半成品误判成已完成。

从父任务进入单牧场子项目后，用户仍可按需点击各分析页。手动生成单场 Excel 成功时，
系统先验证数据阶段，再为已经齐备的核心分析结果和该单场 Excel 提交阶段清单并回写父
任务。若核心结果尚未齐备，单场 Excel 本身仍可使用，但父任务保持“汇总未就绪”，不能
仅凭文件存在被误判为完成。

### 父项目批量分析入口

牧场组父项目的“关键育种性状分析”“牛只指数计算排名”和“近交系数及隐性基因分析”
只负责打开原有参数页面，不得在切换左侧导航时自动开始计算。用户在页面选择性状、指数
权重或分析类型并点击该页面原有的“确认/计算”按钮后，系统只按本次参数逐牧场执行这一项
分析；不会把父项目目录当作单牧场直接计算，也不会同时并行装入多个牧场。每个牧场结束
后，进度列表立即显示“打开”，无论成功、跳过或失败都可以查看该子项目目录。

页面内批量分析只保存各子项目本项结果及独立参数清单，不生成单场综合 Excel、牧场组
汇总 Excel 或 PPT，也不能把父任务的完整 `analysis` / `child_excel` 阶段误标为完成。
相同参数和相同输入可以断点复用；性状顺序、指数权重数值快照或直接输入变化后必须重算。
指数权重必须在点击计算时冻结数值，不能让各牧场在运行途中按同名配置重新读取。

“自动化生成”是完整组任务的唯一启动入口：按依赖顺序逐牧场完成全套分析和单场 Excel，
全部纳入牧场通过提交校验后，再生成最终牧场组汇总 Excel。若中途失败，只保留已经提交
的单场阶段，不生成阶段性组汇总。

仅创建数据的 `data_only` 牧场组可以原地升级为 `analysis`：已经提交并通过校验的数据
阶段保持不变，只把 `analysis` 和 `child_excel` 由按需阶段改成必需阶段。升级必须是
幂等且可恢复的，并受组级运行租约保护；创建时未选择牛群/系谱数据的牧场组不得偷偷改变
数据口径，必须明确拒绝分析。个体选配始终只允许在单牧场子项目中运行。

## 5. 进程与内存模型

桌面主进程只负责队列、状态、进度和用户操作。数据下载完成后，分析和单场报告由独立
子进程一次处理一个牧场：

- 子进程正常退出：校验阶段清单后进入下一牧场；
- 子进程 Python 异常：该牧场失败并继续下一牧场；
- 子进程被系统杀死、原生库崩溃或内存不足：父进程根据退出状态标记 `interrupted`，释放资源并
  继续下一牧场；
- 主程序退出：SQLite 中的已提交阶段保持不变，下次打开从首个未提交阶段继续。

并发默认值为 1。后续可根据可用内存和单场规模允许 2 个并发，但可靠模式不能把所有
牧场同时装入内存。

组级租约由独立后台线程续期，不依赖子进程 stdout 或界面进度回调。牧场纳入范围改变后，
后台仍持有租约防止其他批次并发写入，但在下一业务安全点触发 fencing，当前批次不得发布。

本地上传牧场的原始文件必须在任务启动前复制为子项目内的只读 `input_bundle`，并保存
SHA-256 清单。系统临时目录只能作为导入过程的暂存区，不能作为断点续跑的唯一来源。
母牛与可选配种记录全部完成后，最后写入 `local_data_commit.json`；没有这个提交文件时，
即使母牛 Excel 已存在也必须重做数据阶段。

## 6. 汇总执行模型

最终汇总本身也是一项可恢复任务：

1. 获取组级互斥租约并冻结纳入范围和选择版本；
2. 验证每个子项目阶段清单及全部必需产物；
3. 逐牧场、逐行把跨场排名所需数据写入磁盘 SQLite，不同时持有多个牧场 DataFrame；
4. 在磁盘数据库上按精确十进制建立稳定排名，并流式生成完整排名和全部源行对账分卷；
5. 扫描全部子项目结果，生成文件清单；
6. 生成轻量汇总 Excel，并以相对路径链接明细卷和单场结果；
7. 再次验证选择版本、阶段文件 stat、所有分卷 SHA、源行对账和结果清单；
8. 将 Excel、明细、清单和快照一次性提升为不可变批次，最后原子替换正式指针。

磁盘不足应在写入前或卷边界安全暂停，已完成子项目不受影响。汇总临时库和已经完成的
分卷保存检查点，释放空间后从最后完成卷继续，而不是重新计算全部牧场。

磁盘判断不能只使用压缩 XLSX 大小乘一个固定系数。启动时做保守粗估，运行期间在来源
提交、外排排序、分卷开始和分卷封装等安全点按 SQLite/WAL、排序临时空间、sheet XML 和
ZIP 双份峰值动态复核。SQLite 使用 WAL + `synchronous=NORMAL`，重启时执行
`quick_check`；损坏的未发布索引先隔离再重建，不继续信任。

## 7. Excel 与 PPT 的职责

### 汇总 Excel

仅由牧场组父项目的“自动化生成”入口触发。左侧三个分析页面无论完成多少单项，都不能
直接生成组汇总；最终汇总只读取完整自动化流程已经提交并校验通过的单场结果。

包含：

- 报告说明与计算口径；
- 牧场任务、阶段和异常情况；
- 牧场核心指标对比、关键性状、年份趋势、系谱识别和数据可用性；
- 跨牧场排名预览；
- 完整明细分卷索引；
- 全部结果文件索引；
- 源行、排名、对账、文件和 SHA 完整性校验；
- 单牧场子项目及报告索引。

预览可以只显示头尾样例，但必须明确标注；全量排名必须全部存在于分卷，且可由完整性
校验证明没有遗漏。

### PPT

多牧场不自动生成组级 PPT。各单场 PPT/Excel 仍保留在子项目；组级管理摘要 PPT
只按需手动生成，并且只能从已发布汇总读取，不承载牛只明细，失败不能改变 Excel
报告包的完成状态。

## 8. 故障处理原则

| 故障 | 系统行为 | 是否继续其他牧场 |
| --- | --- | --- |
| 单牧场接口或数据错误 | 记录该牧场失败原因，保留输入和阶段现场 | 是 |
| 单牧场分析子进程崩溃 | 标记中断，可重试 | 是 |
| 程序整体退出 | 已提交阶段保持；再次打开后继续 | 下次继续 |
| 磁盘空间不足 | 在安全点暂停，不发布半成品汇总 | 子项目不受影响 |
| 某个 XLSX 损坏 | 文件清单 `partial`，阻止正式汇总 | 其他文件继续检查 |
| 汇总时修改纳入范围 | 当前批次变为过期，不标记正式 | 需按新范围重汇总 |
| PPT 生成失败 | Excel 报告包仍可用，单独重试 PPT | 不影响计算 |

## 9. 发布前验收门槛

必须至少完成以下测试，才能把本方案作为正式版本发布：

- 真实多牧场数据至少选择数十个牧场，逐牧场核对行数、牧场编号、牛号和指数小数；
- 构造超过 1,048,575 行的跨场结果，验证自动多卷且总行数完全相等；
- 在母牛写完、配种未写完、分析中途、单场 Excel 中途和汇总分卷中途强制终止；
- 重启后只重做未提交阶段，已完成牧场不重复计算；
- 人为破坏一个源 XLSX、修改一个牛号、制造重复牛号及错误牧场编号，正式汇总必须被
  拦截且指出具体牧场和文件；
- 汇总运行中修改纳入范围，旧批次不得标记为当前；
- 用大量任务验证主进程内存峰值不随累计牧场数持续上升；
- 对全部分卷执行 XLSX CRC、SHA-256、源行数/导出行数及任务身份核对。

在这些门槛通过前，不能仅凭少量样本成功就判断多牧场功能已经可发布。

### 2026-07-29 已完成的跨上限验收

- 2 个模拟牧场，每场 525,000 行，合计 1,050,000 行，严格超过 Excel 单表可用数据行；
- 有效排名与源行对账各生成 5 卷，读回均为 1,050,000 行；
- 排名连续覆盖 `1..1,050,000`，逐卷 CRC、SHA、首末排名和 manifest 计数一致；
- 压力脚本逐行核对牧场、牛号、精确指数及顺序，并另做首卷提交后中断续跑验收；
- 本轮实测约 266 秒，最大常驻内存约 259 MiB，无明细截断。

# 慧牧云服务端只读代理

## 目的

桌面客户端不得保存、读取或接收慧牧云 AES 原始密钥。慧牧云牛群数据统一由 Genetic Improve 认证服务代理读取，用户只使用现有软件账号登录。

## 调用链路

1. 客户端从现有令牌管理器读取软件 JWT。
2. 客户端请求 `GET /api/auth/hmy/cows`，请求头使用 `Authorization: Bearer <JWT>`。
3. 认证服务校验 JWT，并再次校验慧牧云功能工号白名单。
4. 认证服务从生产环境变量读取慧牧云接口地址和 AES 密钥，生成当天 `secret` 请求头。
5. 认证服务调用慧牧云 `/outside/yl/cow`，只向客户端返回分页牛群数据。

## 服务端配置引用

- `HMY_API_BASE_URL`：慧牧云接口根地址。
- `HMY_API_AES_KEY`：慧牧云 AES 鉴权值。

上述变量只保存在生产认证服务的受限环境文件中，不得写入代码、文档、日志、安装包或接口响应。

## 接口

`GET /api/auth/hmy/cows`

查询参数：

- `farmCode`：牧场编码，必填。
- `pageSize`：每页数量，范围 1–2000，默认 2000。
- `pageNum`：页码，从 1 开始。

访问控制：

- 无有效 JWT：返回 401。
- 工号不在慧牧云功能白名单：返回 403。
- 服务端慧牧云配置缺失：返回 503。
- 慧牧云上游不可用或响应异常：返回 502。

## 部署与回滚

生产服务为 `genetic-auth-api.service`，工作目录为 `/home/ecs-user/genetic_improve_auth_v2`。部署文件为 `auth_api.py` 和 `hmy_proxy.py`。

部署前必须备份现有代码和环境文件；部署后依次验证：

1. systemd 服务为 active。
2. `/health` 返回 200。
3. 非白名单 JWT 请求返回 403。
4. 白名单 JWT 可通过代理取得一页真实牛群数据。
5. 日志和响应中不出现 AES 密钥或 JWT 原值。

回滚时恢复部署前备份的 `auth_api.py` 和环境文件，移除新增模块后重启认证服务。
